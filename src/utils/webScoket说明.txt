我完全理解你的困惑——这个 `WebSocketClient` 类封装了很多WebSocket的核心逻辑，而且和Pinia状态联动，乍一看确实容易乱。我会**按功能模块拆解**，用通俗的语言讲清楚每个方法/属性的核心作用、执行时机和目的，让你一眼看懂。

### 先明确这个类的核心定位
这个 `WebSocketClient` 是一个**通用的WebSocket长连接工具类**，核心目的是：
- 帮你简化WebSocket的连接、重连、消息收发逻辑；
- 和用户登录状态、心跳状态联动（通过Pinia）；
- 处理心跳包发送、连接异常、自动重连等“脏活累活”；
- 对外暴露简单的API（比如`initConnect()`、`sendMessage()`），不用关心底层细节。

---

### 一、核心属性/状态（constructor里初始化的内容）
先搞懂类里存了哪些数据，后续方法都是围绕这些数据操作：

| 属性名                | 类型      | 核心作用                                                                 |
|-----------------------|-----------|--------------------------------------------------------------------------|
| `config`              | 对象      | 基础配置：重连间隔（3秒）、最大重连次数（10次），无默认WS地址（靠外部传） |
| `_connected`          | 响应式变量 | 标记WS是否**已成功连接**（供Vue组件监听，比如页面显示“已连接/未连接”）    |
| `_connecting`         | 响应式变量 | 标记WS是否**正在连接中**（防止重复调用`initConnect()`）                   |
| `_error`              | 响应式变量 | 存储WS连接/通信的错误信息（供组件捕获错误）                              |
| `_reconnectCount`     | 响应式变量 | 记录当前自动重连的次数（达到10次就停止重连）                             |
| `connected/connecting`| 只读响应式 | 对外暴露的“安全版”状态（防止外部随便修改，只能读）                        |
| `ws`                  | null/对象 | 存储原生的`WebSocket`实例（真正和后端建立连接的核心对象）                 |
| `reconnectTimer`      | null/定时器 | 自动重连的定时器ID（用于清除重连定时器）                                 |
| `customWsUrl`         | 字符串    | 存储外部传入的自定义WS地址（比如登录后从后端拿到的地址）                 |
| `xxxCallback`         | null/函数 | 存储外部注册的回调函数（比如连接成功后要执行的逻辑、收到消息后要做的事）  |

### 二、核心方法拆解（按功能分类）
#### 🔹 第一类：WS地址相关方法（处理连接地址）
| 方法名         | 核心作用                                                                 | 执行时机                                  |
|----------------|--------------------------------------------------------------------------|-------------------------------------------|
| `setWsUrl(url)` | 给WS客户端设置**自定义连接地址**（比如登录后从后端拿到的`ws://xxx`地址）| 登录成功后、初始化WS前调用（比如`initWebSocketService`里） |
| `getWsUrl()`   | 拼接最终要使用的WS地址：<br>1. 优先用`customWsUrl`（外部传的自定义地址）；<br>2. 没有的话，自动生成默认地址（`ws://localhost:8094/ws`） | 每次调用`initConnect()`时，都会先调用这个方法拿地址 |

#### 🔹 第二类：心跳相关方法（维持长连接）
| 方法名         | 核心作用                                                                 | 执行时机                                  |
|----------------|--------------------------------------------------------------------------|-------------------------------------------|
| `sendHeartbeat()` | 发送**心跳包**给后端（格式：`heartbeat|用户ID|应用名称`），维持长连接 | 1. 心跳定时器每秒触发，倒计时到0时调用；<br>2. WS连接成功后也会触发 |
|                | 👉 额外校验：必须满足“WS已连接 + 有登录用户ID + 有应用名称”才会发心跳 | 👉 不满足就打印警告，不发心跳（避免无效请求） |

#### 🔹 第三类：连接核心方法（最关键的`initConnect()`）
`initConnect()` 是整个类的“入口”，负责**创建WS连接、绑定各类回调**，是核心中的核心。
我拆解开里面的关键逻辑：

| 内部逻辑块       | 核心作用                                                                 |
|------------------|--------------------------------------------------------------------------|
| 前置校验         | 先判断：如果正在连接中/已连接，直接返回（防止重复连接）                   |
| 创建WS实例       | 调用`getWsUrl()`拿到地址，创建原生`WebSocket`实例（`this.ws = new WebSocket(地址)`） |
| `ws.onopen`      | WS**连接成功后**执行的逻辑：<br>1. 更新状态（已连接、停止连接中、重置重连次数）；<br>2. 给后端发“绑定用户”消息（`bind|用户ID|应用名称`）；<br>3. 如果用户已登录且心跳没启动，自动启动心跳；<br>4. 执行外部注册的`openCallback`（比如页面提示“连接成功”） |
| `ws.onmessage`   | WS**收到后端消息后**执行的逻辑：<br>1. 解析后端消息（区分“绑定成功”“心跳响应”“登录过期”等）；<br>2. 如果是业务消息（JSON），传给外部的`messageCallback`；<br>3. 如果收到`expired`（登录过期），自动触发用户登出 + 关闭WS |
| `ws.onerror`     | WS**连接/通信出错时**执行：<br>1. 记录错误信息到`_error`；<br>2. 执行外部的`errorCallback`（比如页面提示“连接异常”） |
| `ws.onclose`     | WS**连接关闭时**执行：<br>1. 更新状态（未连接、停止连接中）；<br>2. 停止心跳定时器（避免给断开的WS发心跳）；<br>3. 调用`handleReconnect()`触发自动重连；<br>4. 执行外部的`closeCallback`（比如页面提示“连接断开”） |
| 异常捕获         | 如果创建WS实例失败（比如地址错误），记录错误 + 触发重连                   |

#### 🔹 第四类：自动重连方法
| 方法名           | 核心作用                                                                 | 执行时机                                  |
|------------------|--------------------------------------------------------------------------|-------------------------------------------|
| `handleReconnect()` | 处理**自动重连逻辑**，避免WS断连后需要手动重连：<br>1. 先判断：如果已连接/重连次数超10次，停止重连；<br>2. 否则，3秒后调用`initConnect()`重新连接；<br>3. 重连次数+1，打印日志 | 1. WS连接关闭时（`onclose`）；<br>2. WS初始化失败时 |

#### 🔹 第五类：消息发送/连接关闭方法
| 方法名           | 核心作用                                                                 | 执行时机                                  |
|------------------|--------------------------------------------------------------------------|-------------------------------------------|
| `sendMessage(data)` | 通用的**消息发送方法**（给后端发任意消息）：<br>1. 校验：WS未连接则报错，返回false；<br>2. 自动处理数据格式（对象转JSON字符串，字符串直接发）；<br>3. 打印发送日志，返回是否发送成功 | 1. 发送心跳包（`sendHeartbeat()`里调用）；<br>2. 发送绑定用户消息（`onopen`里）；<br>3. 组件手动发业务消息（比如聊天消息） |
| `closeConnect()` | 手动**关闭WS连接**：<br>1. 清除重连定时器（防止关闭后还重连）；<br>2. 关闭原生WS实例；<br>3. 重置所有连接状态（未连接、重连次数归0） | 1. 用户登出时；<br>2. 收到后端`expired`（登录过期）时；<br>3. 组件手动调用（比如页面关闭时） |

#### 🔹 第六类：回调注册方法
| 方法名           | 核心作用                                                                 | 执行时机                                  |
|------------------|--------------------------------------------------------------------------|-------------------------------------------|
| `on({open, message, error, close})` | 给WS注册**全局回调函数**（让外部代码能监听WS事件）：<br>比如：<br>- `open`：连接成功后要执行的逻辑（比如弹“连接成功”提示）；<br>- `message`：收到后端消息后要做的事（比如渲染聊天记录）；<br>- `error`：出错后要做的事（比如弹错误提示） | 初始化WS后调用（比如`initWebSocketService`里） |

#### 🔹 最后：导出内容
| 导出项           | 核心作用                                                                 |
|------------------|--------------------------------------------------------------------------|
| `wsClient`       | 类的**单例实例**（全局唯一的WS连接，整个项目都用这一个，不用重复创建）     |
| `WebSocketClient`| 类本身（供特殊场景创建多实例，比如同时连多个WS地址，一般用不到）           |

### 核心执行流程（帮你串起来）
用“用户登录”这个场景，串一遍整个类的调用逻辑，你就全懂了：
1. 登录成功 → 调用`wsClient.setWsUrl(后端给的WS地址)` → 给WS客户端设置自定义地址；
2. 调用`wsClient.initConnect()` → 内部调用`getWsUrl()`拿到地址，创建WS实例；
3. WS连接成功（`onopen`）→ 给后端发`bind|用户ID|应用名称`绑定用户 → 自动启动心跳定时器；
4. 心跳定时器每秒触发 → 倒计时到0 → 调用`sendHeartbeat()`发心跳包；
5. 如果WS断连（比如网络断了）→ `onclose`触发 → 调用`handleReconnect()` → 3秒后自动重连；
6. 用户登出 → 调用`wsClient.closeConnect()` → 关闭WS连接，停止重连；
7. 收到后端消息 → `onmessage`触发 → 执行你注册的`messageCallback` → 处理业务逻辑（比如显示消息）。

### 总结（关键点回顾）
1. `WebSocketClient` 是**封装层**：把原生WebSocket的复杂逻辑（连接、重连、心跳）包起来，对外只暴露简单API；
2. 核心入口是`initConnect()`：所有连接、回调绑定都从这开始；
3. 核心联动点：和Pinia的用户/心跳状态绑定（比如登录过期自动登出、WS断连停止心跳）；
4. 核心保障：自动重连（最多10次）、防止重复连接、响应式状态供组件监听。

这样拆解后，你可以先聚焦核心方法（`initConnect()`、`sendMessage()`、`closeConnect()`），其他方法都是为这三个核心服务的，理解起来就容易多了。
